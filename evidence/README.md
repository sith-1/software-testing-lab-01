# Доказательства

Папка для материалов, подтверждающих результаты проверок. Документы лабораторной ссылаются сюда, но **сами доказательства в репозиторий не добавляются**, пока в них есть данные реальных людей или служебная информация стенда.

## 1. Что прикладывается

| Тип | Когда нужен | Формат |
| --- | --- | --- |
| Скриншот сообщения об ошибке или об успехе | CH-A-06, CH-B-09, CH-D-06, CH-E-03, CH-F-02 | `.png` |
| Журнал сетевых запросов (HAR) | BUG-02, CH-G-05, CH-F-06 | `.har` или фрагмент в `.txt` |
| Тело ответа API и код ответа | BUG-03, CH-B-06, CH-F-04 | `.json` |
| Запись экрана с двойным нажатием | CH-G-01 | `.mp4` |
| Отчёт автоматического прогона | CH-A-02, CH-A-03, CH-B-05, CH-D-03 | `.txt` или `.xml` |
| Скриншот журнала сервера | CH-C-01, CH-F-06 | `.png` |

## 2. Правила именования

```text
<ID проверки или дефекта>_<краткое описание>_<ГГГГ-ММ-ДД>.<расширение>
```

Примеры:

```text
CH-G-01_double-click_two-records_2026-11-06.png
BUG-03_response-body_2026-11-06.json
CH-D-03_boundary-18-years_2026-11-06.txt
```

## 3. Запрещено

- Реальные адреса электронной почты, имена и даты рождения людей. Используются тестовые значения вида `ivan.test.01@example.com`.
- Пароли в открытом виде, токены, ключи, строки подключения к базе данных.
- Идентификаторы стенда, внутренние адреса и учётные данные администратора.
- Файлы, создаваемые IDE (`.idea/`, `.vscode/`), и результаты сборки.

## 4. Если доказательство содержит чувствительные данные

1. Замазать или обрезать чувствительные поля.
2. Проверить результат после редактирования: не осталось ли данных в метаданных изображения.
3. Приложить файл в папку и убедиться, что он открывается у другого человека.

Если обезличить материал нельзя, он не прикладывается: в отчёте о дефекте достаточно указать, что доказательство предоставляется по запросу.
